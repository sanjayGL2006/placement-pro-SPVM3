## 1. Executive Summary & Host Architecture Split

Placement Pro supports dual host deployment targets. Do not confuse static preview environments with live serverless / full-stack environments.

```
                  ┌────────────────────────────────────────────────────────┐
                  │                 Placement Pro App                      │
                  └───────────────────┬────────────────────────────────────┘
                                      │
           ┌──────────────────────────┴──────────────────────────┐
           ▼                                                     ▼
┌───────────────────────────────┐                     ┌───────────────────────────────┐
│     GitHub Pages Demo         │                     │  Vercel / Docker / Flask      │
│  (Static HTML / CSS / JS)     │                     │     (Full Stack REST API)     │
├───────────────────────────────┤                     ├───────────────────────────────┤
│ • Pre-rendered HTML routes    │                     │ • Python Flask REST API       │
│ • Client-side JS (api.js)     │                     │ • JWT Argon2id Auth           │
│ • LocalStorage mock fallback  │                     │ • PostgreSQL / SQLite DB      │
│ • No PHP / SQLite execution   │                     │ • Real File Imports & PDFs    │
└───────────────────────────────┘                     └───────────────────────────────┘
```

### Host Split Rules & Best Practices

1. **GitHub Pages (Static Demo)**:
   - Serves pre-rendered `.html` files generated by `render_previews.py`.
   - Cannot run PHP scripts or write to SQLite databases.
   - All REST API calls automatically fallback to client-side `mock-data.json` and `localStorage` keys (`pp_mock_students_v2`, `pp_mock_companies_v2`).

2. **Vercel (Serverless Full Stack)**:
   - Configured via [`vercel.json`](file:///c:/Users/Sanjay%20G%20L/Desktop/placement-pro/vercel.json) with explicit rewrites:
     - `/api/(.*)` ➔ `/api/index.py` (Flask REST API Serverless Function)
     - `/assets/(.*)` ➔ `/frontend/assets/$1`
     - `/(.*)` ➔ `/frontend/previews/$1`
   - Requires Environment Variables set in Vercel Dashboard (`DATABASE_URL`, `JWT_SECRET`, `SECRET_KEY`, `CORS_ORIGINS`).
   - Uses serverless-friendly PostgreSQL connection pooling (Neon / Supabase PgBouncer).

3. **Case Sensitivity & URL Rules**:
   - Linux host environments (GitHub Pages & Vercel) enforce strict case sensitivity. All links must match exact file casing (e.g. `dashboard.html` not `Dashboard.html`).
   - API endpoints use relative paths (`/api`) or dynamic base resolution (`window.location.origin + '/api'`) with zero hardcoded `localhost` URLs in production.

## 5. Suggested Execution Order

### Phase 1: On GitHub Pages (Static Deployment)
1. **Smoke Pass**: Visit every static HTML route via sidebar navigation.
2. **QA Regression Check**: Verify no `.php` 404 links, `₹ LPA` currency rendering, PESIAMS department names, local SweetAlert2 asset loading.
3. **UI + Viewport Testing**: Test dashboard, students directory, companies directory on 375px, 768px, 1280px widths.
4. **Offline Mock Data Persistence**: Perform mock CRUD operations and refresh page to verify `localStorage` persistence (`pp_mock_students_v2`, `pp_mock_companies_v2`).
5. **Exploratory & PWA Verification**: Test Service Worker registration, AI Hub UI, and drag-and-drop import dropzone.

### Phase 2: With Live REST API (Vercel / Flask / Docker)
1. **Automated Unit & API Tests**:
   ```powershell
   & "backend/venv/Scripts/python.exe" -m pytest backend
   ```
2. **Integration Verification**: Test authentication (`POST /api/auth/login`), JWT validation (`GET /api/auth/me`), student CRUD, and soft/hard resets.
3. **Import Commit Pipeline**: Upload real `.xlsx`, `.csv`, `.docx`, and `.pdf` files to test fuzzy header mapping and DB insertion.
4. **Serverless & Environment Checks**: Confirm `vercel.json` rewrites `/api/(.*)` to `/api/index.py` and environment variables (`DATABASE_URL`, `JWT_SECRET`) are configured.
